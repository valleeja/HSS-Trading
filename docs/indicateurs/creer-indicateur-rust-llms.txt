# Argos HSS Trading — writing indicators in Rust, reference for AI assistants (v2, 2026-11-22)

There are two paths: a WASM module that anyone can build and load without recompiling the app (lines, labels and cards only), or a native indicator compiled into the app (full drawing, for contributors).
When Rust is not needed, an Argos Script indicator (Pine-like script stored in the catalogue) is simpler: settings, drawing and the { } button come for free.
State on 2026-11-22: kit-module-argos 1.0.2 (vendored in the repository under rust/vendor/kit-module-argos-1.0.2), Rust 1.99.1, module ABI v2; the kit tool argos-modules, module signing and shapes/tables/alerts output are not available yet.

Sources: the kit files (LISEZ-MOI.md, INTERFACE-V2.md, argos-module-sdk/src/data.rs and lib.rs, argos-module-policy/src/settings.rs and lib.rs, exemple-moyenne/), the Trading host crate argos-module-host, and the French doc "Créer un indicateur en Rust" (documents/2026-11-22-creer-indicateur-rust-v2.md). When this file and the kit disagree, the kit is the reference.

## Rules for writing an Argos module

1. Produce three files: Cargo.toml, src/lib.rs, argos-module.json.
2. src/lib.rs starts with #![forbid(unsafe_code)], defines one fn run(input: Input) -> Output and ends with argos_module_sdk::entry_data!(run);
3. Everything crossing the ABI is an integer: prices are scaled by input.price_scale, volumes by input.volume_scale; a missing value is i64::MIN; use i128 for sums.
4. Output only lines (at most 16, exactly one value per bar), labels (at most 1000, text at most 256 bytes) and cards (at most 32). No shapes, tables or alerts.
5. Manifest: "path" starts with "trading/", "abi": 2, capabilities empty or only ReadFiles / WriteFiles; Network, Ai and Model are refused; unknown fields are refused.
6. Settings: at most 16, types number / bool / color / choice; values arrive in input.settings as i64, in manifest order.
7. Dependencies only from allowed-dependencies.txt with exact versions; no build.rs, no git dependency; crate-type = ["cdylib", "rlib"], publish = false, empty [workspace].
8. Build: cargo build --release --target wasm32-unknown-unknown (the kit tool argos-modules is not available yet).
9. Limits: budget_secs (default 2, 1 to 120), 200,000,000 fuel per call, 16 MiB memory, 4 MiB input, 50,000 bars (oldest cut).
10. Modules are not signed yet: the user approves the SHA-384 of the .wasm at install time.

Additional rules from the kit: no WASI, no unsafe in the module, no key in the code, no procedural macros (serde derive is refused), money never in f64 (use rust_decimal or scaled integers). The module may compute in floating point internally but must return integers.

## Module ABI v2

### Exports

A v2 module exports exactly these (generated by entry_data!):

| Export | Signature | Meaning |
| --- | --- | --- |
| memory | linear memory | required |
| argos_abi | () -> i32 | returns 2 |
| alloc | (len: i32) -> i32 | returns the address of a zeroed buffer of len bytes, or -1; the kit leaks it (a fresh instance serves every call) |
| free | (ptr: i32, len: i32) | no-op |
| run_data | (ptr: i32, len: i32) -> i64 | runs the module; negative = status, else (output address << 32) bitwise-OR output length |

A v2 module must not export run (the v1 entry); a v1 module must not export run_data, alloc, free or argos_abi. Mixtures are refused by the host. Trading only runs v2 modules.

### Imports

Only from the WASM import module "argos": read_file, write_file, network_request, ai_request, model_request, each (ptr: i32, len: i32, out_ptr: i32, out_cap: i32) -> i32. The SDK wraps them as fn name(request: &[u8], out: &mut [u8]) -> Result<usize, HostError>. A function never called is never imported. In Trading only read_file / write_file can work (private folder, if the user grants it); outside wasm32 every call returns HostError::Unavailable.

HostError: TooLarge (does not fit 32 bits), Unavailable (no host), Status(i32) (host refused, negative status).

### One call, host side

1. Check argos_abi() == 2.
2. Encode the input; refuse if over 4 MiB.
3. ptr = alloc(len); refuse if negative or ptr + len exceeds memory.
4. Copy the input to ptr; call run_data(ptr, len).
5. Negative result = module error status. Otherwise high 32 bits = output pointer, low 32 bits = length; refuse length over 4 MiB or bytes outside memory.
6. Decode and validate the output. Fuel, memory and time limits apply to the whole call.

run_data statuses: -1 bad input, -2 output over 4 MiB, -3 no input memory (not running in the sandbox).

### Encoding (little-endian, no padding)

Strings: u16 length then UTF-8 bytes. Integers fixed width. EMPTY = i64::MIN. Anything malformed (wrong version, length past the end, trailing bytes, invalid UTF-8, limit exceeded) is refused, never partly used.

Input:

| Field | Type | Limits |
| --- | --- | --- |
| abi | u32 | = 2 |
| timeframe | u32 | seconds, > 0 |
| price_scale | u8 | 0..=12 in the kit; Trading sends at most 8 |
| volume_scale | u8 | 0..=12 in the kit; Trading sends at most 6 |
| symbol | string | 1..=32 bytes |
| bar count | u32 | 0..=50,000 |
| bars | count x (t, o, h, l, c, v: i64) | 48 bytes each, t (Unix seconds) strictly increasing |
| setting count | u16 | 0..=16 |
| settings | count x i64 | manifest order |

Output:

| Field | Type | Limits |
| --- | --- | --- |
| abi | u32 | = 2 |
| line count | u16 | 0..=16 |
| lines | count x (name: string 1..=64, scale: u8 0..=12, value count: u32 = bar count, values: i64) | EMPTY = no value |
| label count | u16 | 0..=1000 |
| labels | count x (bar: u32 < bar count, text: string 1..=256) | |
| card count | u16 | 0..=32 |
| cards | count x (name: string 1..=64, value: i64, scale: u8 0..=12) | |

### SDK types (argos_module_sdk::data, re-exported at the crate root)

```rust
pub struct Bar { pub t: i64, pub o: i64, pub h: i64, pub l: i64, pub c: i64, pub v: i64 }
pub struct Input {
    pub timeframe: u32,      // bar duration in seconds
    pub price_scale: u8,     // decimals of prices (12345 at scale 2 = 123.45)
    pub volume_scale: u8,    // decimals of volumes
    pub symbol: String,
    pub bars: Vec<Bar>,      // oldest first, t strictly increasing
    pub settings: Vec<i64>,  // manifest order
}
pub struct Line  { pub name: String, pub scale: u8, pub values: Vec<i64> } // one value per input bar
pub struct Label { pub bar: u32, pub text: String }
pub struct Card  { pub name: String, pub value: i64, pub scale: u8 }
pub struct Output { pub lines: Vec<Line>, pub labels: Vec<Label>, pub cards: Vec<Card> }
```

All derive Debug, Clone, PartialEq, Eq, Default (Bar also Copy). Root re-exports: `use argos_module_sdk::{Bar, Card, DecodeError, Input, Label, Line, Output, EMPTY};` (the path argos_module_sdk::data::... also works).

Constants (argos_module_sdk::data): ABI = 2, EMPTY = i64::MIN, MAX_BYTES = 4 MiB, MAX_BARS = 50_000, MAX_SETTINGS = 16, MAX_LINES = 16, MAX_LABELS = 1000, MAX_CARDS = 32, MAX_SCALE = 12. DecodeError: Truncated, Trailing, Version, Invalid, TooLarge. Input::encode / Input::decode(bytes), Output::encode / Output::decode(bytes, bars).

The SDK is #![no_std] with alloc; a module can still use std (the example uses Vec and format!).

### Conversion by the Trading host (argos-module-host)

- input_of: keeps the last 50,000 bars, picks price_scale (at most 8) and volume_scale (at most 6) from the data, converts each f64 once with round(x x 10^scale); a non-finite value becomes EMPTY; bars with non-increasing time are dropped; symbol stripped of control characters, cut to 32 bytes, "?" if empty; timeframe clamped to at least 1.
- fenetre: also drops the oldest bars until the encoded input fits 4 MiB, and counts the bars left out (shown in the interface).
- Back: lines_of converts each value to f64 with its line's scale (EMPTY becomes NaN); cards_of formats each card with fixed(value, scale) (for example -150 at scale 2 is "-1.50").
- Lines are drawn on the price when they share the price scale; keeping scale = input.price_scale means no conversion.

## Manifest argos-module.json

Read with serde deny_unknown_fields: any unknown field is refused.

| Field | Type | Default | Rule in Trading |
| --- | --- | --- | --- |
| path | string | required | starts with "trading/"; the name after it is 1 to 64 characters of letters, digits, -, _, / |
| version | u64 | required | integer that always goes up |
| author | string | required | Argos ID of the author |
| abi | u32 | 1 | must be 2 (so always write it) |
| capabilities | list | [] | only "ReadFiles", "WriteFiles"; "Network", "Ai", "Model" refused |
| settings | list of SettingSpec | [] | at most 16, see Settings |
| budget_secs | u32 | 2 | 1 to 120 seconds |
| subfolders | list of strings or absent | absent | allowed subfolders of the private folder |
| domains | list of strings | [] | kit field for Network (HTTPS lowercase DNS names, no IP, no localhost, at most 32); useless in Trading since Network is refused |
| ai_model | string or absent | absent | kit field for Ai; useless in Trading |
| model | string or absent | absent | kit field for Model (96 hex chars SHA-384); useless in Trading |

Kit rules (ServicePolicy::check): budget 1 to 120 s; at most 32 domains or subfolders; abi 1 or 2, a v1 module has no settings; setting ids unique. Trading checks its rules first, then the kit's.

Minimal manifest:

```json
{
  "path": "trading/my-average",
  "version": 1,
  "author": "<your Argos ID>",
  "abi": 2,
  "settings": [
    { "id": "length", "name": "Longueur", "type": "number", "default": 20, "min": 1, "max": 500 }
  ]
}
```

## Settings (SettingSpec)

JSON form, one object per setting: id, name, type, default, plus min / max / scale for number and choices for choice. A field the type does not use is refused, and so is an unknown field.

```json
{ "id": "length", "name": "Longueur", "type": "number", "default": 20, "min": 1, "max": 500, "scale": 0 }
{ "id": "show", "name": "Afficher", "type": "bool", "default": true }
{ "id": "color", "name": "Couleur de la ligne", "type": "color", "default": "#2962ff" }
{ "id": "mode", "name": "Mode", "type": "choice", "choices": ["a", "b"], "default": "a" }
```

| Type | Fields | Value given to the module (i64) |
| --- | --- | --- |
| number | default, min, max (integers at the scale), scale (0 to 6, default 0) | the integer at its scale: 150 at scale 2 means 1.50 |
| bool | default (JSON true / false) | 1 or 0 |
| color | default "#rrggbb" (upper or lower case hex) | 0xRRGGBB |
| choice | choices (1 to 32, unique, each 1 to 64 bytes), default (one of the choices) | index of the choice, 0 for the first |

Limits: at most 16 settings; id 1 to 32 characters of letters, digits, - or _, unique; name 1 to 64 bytes without control characters; number needs min <= default <= max. The host checks every value against the manifest before each call (check_values): the module always receives allowed values, but it should still not panic on anything. Settings are not rights; they are part of the module's policy, and changing them means a new version. Argos draws the ⚙ settings window from the manifest (PC and web).

## Build and install

Build (from the module folder, placed next to argos-module-sdk/ so that path = "../argos-module-sdk" resolves):

```
rustup target add wasm32-unknown-unknown
cargo build --release --target wasm32-unknown-unknown
```

The file lands in target/wasm32-unknown-unknown/release/<crate_name>.wasm (hyphens in the package name become underscores in the file name). Toolchain: Rust 1.99.1 (the kit's rust-toolchain.toml pins it, with rustfmt, clippy and the wasm32 target).

Official path, not available yet: cargo generate-lockfile, then from the kit folder ./argos-modules build my-module out . --offline (fmt, clippy, test, audit, deny, two identical WASM builds, writes out/module.wasm and out/proposal.json). The binary is missing from the vendored copy.

Inside the repository, make modules builds the kit example and rust/modules/* with CARGO_TARGET_DIR=target/modules and copies them to app/modules/<name>.wasm and .json; make check runs clippy and tests of each rust/modules/* crate. Repository modules point to the SDK with ../../vendor/kit-module-argos-1.0.2/argos-module-sdk.

Install on PC: put <name>.wasm and <name>.json (or argos-module.json) in the Downloads folder (~/Téléchargements or ~/Downloads), then open the 🧩 Modules page and press "📂 Installer un module". All .wasm / .json pairs found are read. The app parses the manifest, checks it, scans the exports and imports, and stores the approved SHA-384. Installed modules are kept under ~/.config/argos-hss-trading/charts/modules/.

Install on the web: the same button opens a file picker (.wasm, .json). The module runs in a Web Worker, stopped after max(50 ms, budget) + 300 ms.

On the 🧩 Modules page: start, stop, rights (only the private folder, 1 MiB quota), generated settings, remove; also import / export of argos-catalogue.json.

Built-in example modules (embedded in the app): moyenne (the kit example), ema (EMA seeded by the SMA, scale price_scale + 4), academie (New York session high/low windows: Asia, London, ORB, Silver Bullet; 2 lines, labels, 3 cards), pinceau-zone (volume by price, POC, VAH/VAL, VWAP, estimated delta of a rectangle zone, opened by right click on a rectangle). Sources in rust/modules/.

The Tauri shell is still on wasmtime 50.0.1 (app: 50.0.2) and only runs embedded modules listed in its approbations.json.

## Complete example

### Example of the French doc (simple, truncating average)

argos-module.json:

```json
{
  "path": "trading/ma-moyenne",
  "version": 1,
  "author": "<ton Argos ID>",
  "abi": 2,
  "settings": [
    { "id": "length", "name": "Longueur", "type": "number", "default": 20, "min": 1, "max": 500 }
  ]
}
```

src/lib.rs:

```rust
#![forbid(unsafe_code)]
use argos_module_sdk::{Card, Input, Line, Output, EMPTY}; // EMPTY = valeur absente

pub fn run(input: Input) -> Output {
    // Réglage 0 = Longueur (number, scale 0)
    let len = input.settings.first().copied().unwrap_or(20).clamp(1, 500) as usize;
    let closes: Vec<i64> = input.bars.iter().map(|b| b.c).collect();
    let mut values = vec![EMPTY; closes.len()];
    let mut sum: i128 = 0;
    for (i, c) in closes.iter().enumerate() {
        sum += i128::from(*c);
        if i >= len {
            sum -= i128::from(closes[i - len]);
        }
        if i + 1 >= len {
            values[i] = (sum / len as i128) as i64;
        }
    }
    let last = values.last().copied().unwrap_or(EMPTY);
    Output {
        lines: vec![Line { name: "Moyenne".into(), scale: input.price_scale, values }],
        labels: vec![],
        cards: vec![Card { name: "Dernière moyenne".into(), value: last, scale: input.price_scale }],
    }
}

argos_module_sdk::entry_data!(run);
```

```rust
//! Example Argos interface v2 module: the simple moving average of the bars.
//! No rights at all: it receives the bars and its settings, and returns one
//! line and one card. Integers only: the average keeps the price scale and
//! is rounded half away from zero.
#![forbid(unsafe_code)]

use argos_module_sdk::{Bar, Card, Input, Line, Output, EMPTY};

/// Default length, as in `argos-module.json`.
pub const DEFAULT_LENGTH: i64 = 20;
/// Largest length, as in `argos-module.json`.
pub const MAX_LENGTH: i64 = 500;

/// The bar value a `source` setting picks (index of its choice).
fn pick(bar: &Bar, source: i64) -> i64 {
    match source {
        1 => bar.o,
        2 => bar.h,
        3 => bar.l,
        _ => bar.c,
    }
}

/// `sum / n` rounded half away from zero (`n > 0`).
fn rounded_div(sum: i128, n: i128) -> i128 {
    let half = n / 2;
    if sum >= 0 {
        (sum + half) / n
    } else {
        (sum - half) / n
    }
}

/// The moving average of `values` over `length`: [`EMPTY`] until the window
/// is full or while it holds an [`EMPTY`] value.
pub fn moving_average(values: &[i64], length: usize) -> Vec<i64> {
    let mut out = Vec::with_capacity(values.len());
    let mut sum: i128 = 0;
    let mut empty = 0_usize;
    let n = i128::try_from(length).unwrap_or(i128::MAX);
    for (i, &value) in values.iter().enumerate() {
        if value == EMPTY {
            empty += 1;
        } else {
            sum += i128::from(value);
        }
        if let Some(old) = i.checked_sub(length).map(|j| values[j]) {
            if old == EMPTY {
                empty -= 1;
            } else {
                sum -= i128::from(old);
            }
        }
        let full = i + 1 >= length && length > 0 && empty == 0;
        out.push(if full {
            // The average of i64 values always fits an i64.
            i64::try_from(rounded_div(sum, n)).unwrap_or(EMPTY)
        } else {
            EMPTY
        });
    }
    out
}

/// Entry logic: settings `length` (1 to 500) and `source` (close, open,
/// high, low). The host checked them; a value out of bounds still gives a
/// line of [`EMPTY`] values, never a panic.
pub fn run(input: Input) -> Output {
    let length = input.settings.first().copied().unwrap_or(DEFAULT_LENGTH);
    let source = input.settings.get(1).copied().unwrap_or(0);
    let length = usize::try_from(length)
        .ok()
        .filter(|l| (1..=500).contains(l))
        .unwrap_or(0);
    let values: Vec<i64> = input.bars.iter().map(|b| pick(b, source)).collect();
    let average = moving_average(&values, length);
    let last = average.last().copied().unwrap_or(EMPTY);
    Output {
        lines: vec![Line {
            name: format!("Moyenne {length}"),
            scale: input.price_scale,
            values: average,
        }],
        labels: Vec::new(),
        cards: vec![Card {
            name: "Dernière moyenne".into(),
            value: last,
            scale: input.price_scale,
        }],
    }
}

argos_module_sdk::entry_data!(run);
```

Testing a module: the logic is plain Rust, so cargo test works natively (build an Input by hand with Bar values, call run, check out.lines[0].values). Host calls return HostError::Unavailable outside wasm32.

## Native indicator (contributors)

A native indicator implements no trait: it is a pure computation in the argos-script crate, a variant at the end of the enum Ind, a card (fiche) in the catalogue and a drawing in the argos-render crate. Example files to read: the multi-timeframe table (argos-script/src/indicators/mtf_table.rs, drawn by draw_mtf_table in argos-render/src/indicators/tables.rs) and the EMA cross (ema_cross_n in argos-script/src/indicators/classic.rs). SMA, WMA, HMA, VWMA, SMMA and MA Ribbon are not native: they are Pine scripts played by Argos Script (argos-script/src/integres.rs).

### Checklist to add an indicator Foo

1. Computation: argos-script/src/indicators/foo.rs with GROUPS, PARAMS, a compute(bars, ...) function and its #[cfg(test)] tests; add pub mod foo; in argos-script/src/indicators/mod.rs. Read settings with Inputs { params: &PARAMS, vals } and .get / .len / .on / .pick / .rgb / .opacity / .source(key) (argos-script/src/inputs.rs; an unknown key panics in tests). Primitives in argos-script/src/ta.rs: sma, ema(src: &[f64], len) -> Vec<f64>, rsi.
2. Render: add Foo at the end of enum Ind and of Ind::ALL (argos-render/src/indicators/mod.rs; the array length grows by one). For a band (sub-pane) indicator also oscillator() / default_h. Either:
   - simple lines: a branch in plot() (argos-render/src/indicators/classic_plots.rs, before the final `_ => return None`) returning a Plot (fields sub, lines: Vec<(Vec<f64>, Rgb, f32)>, hist, zones, bars, levels, range, marks, fill, dash, tableau: Vec<(&str, String)>); legend, signals, summary table and line style come automatically; or
   - a field in IndOut, plus a branch in compute (runs only when active and with more than 30 bars) and in draw (called every frame), with the drawing in tables.rs / zones.rs / osc.rs.
   Optionally expose outputs to other indicators in source_outputs.
3. Catalogue: a fiche at the end of FICHES and exactly one category in CATEGORIES_FX (argos-script/src/catalogue.rs); search words in MOTS_CLES if needed; marketplace entry in MARCHE optional. The fiche id is format!("{:?}", Ind). PC and phone menus fill themselves.
4. { } button: add Ind::Foo => include_str!("...") in argos-render/src/sources.rs. Without this line there is no button: that is the case today for all 40 Rust indicators (only the 5 Pine-backed natives and Script fiches have one).
5. Optional: English name in DICT (argos-render/src/i18n.rs), default indicator (DEFAUTS / NOUVEAUX in argos-desktop/src/actions/murs.rs), reading by Argos AI (READ_BY_RULES in the argos-ai crate, roles_of and read in its rules module, count in its tests).
6. Update the hard-coded counts in tests (tous_les_indicateurs in argos-render/src/indicators/mod.rs, catalogue tests), then cd rust && make check (includes clippy for wasm32).

### Settings constructors

Each setting is a pair (key, f64 value), declared in a const PARAMS: [Param; N] with GROUPS. Constructors (key, group, label, default...) in argos-script/src/inputs.rs: int, num (min, max, step), check, choice, color (0xRRGGBB), color_t (with transparency), price, time, session, string, text_area, symbol, source (default index). Options: .tip, .inline, .active_if, .display, .confirm. Values are f64 in table order (checkbox 0/1, colour u32 with transparency in bits 24-30); defaults(params) gives the defaults. Settings are saved by key name in indicator_settings.json; a new key goes at the end of the table. The ⚙ window is generated from Ind::params() on PC and phone.

Example (multi-timeframe table): GROUPS = ["⚙️ Calcul", "📊 Unités de temps"], int("fast", 0, "EMA rapide", 20.0, 2.0, 200.0), check("m15", 1, "15m", true).

### Drawing API (argos-render, tiny_skia Pixmap)

- Geometry: Geo with x(i), y(price), slot(i), xf, price_area(), right().
- Lines: poly_trait(pm, pts: &[(f64, f64)], c: Rgb, w: f32, dash: usize), seg, seg_couleurs, tirets, shapes::lines / lines_alpha.
- Areas and shapes: zone(pm, g, from, to, top, bot, c, alpha), cloud, dot, shapes::round_fill / round_stroke / poly_fill / Rect::new.
- Text: Text::draw(pm, s, (x, y), size, color, Align), Text::width.
- Tables: table(pm, text, area, title, rows: &[(&str, String)], inp, prefix) with settings tblPos / tblSize (never overlapping; "Tableau trop grand…" if it cannot fit).
- Pills: tag, shapes::pilule.
- No overlap: poser_tableau(r) -> bool, tableaux(), reserver / hors_reserve, set_eviter / eviter(), reset every frame.
- Colours: palette::up() / down(), GOLD, hex(0xRRGGBB), EMA_COLORS, col(&inp, key), and on_chart(c) for light theme and colour-blind mode.
- Free buy/sell signals for a line indicator: signals(crosses(a, b), "Achat", "Vente") in plot(). Free summary table: fill Plot.tableau (keys showTable / tblPos / tblSize).

### Tests

Computation tests in the same file (#[cfg(test)], a bars(n, ...) helper, crate::inputs::defaults(&PARAMS)). Render tests: tous_les_indicateurs (hard-coded counts of plots and classics). Catalogue tests: catalogue_identique_a_avant, catalogue_coherent. App tests: add / favourite / remove of every Ind, { } button, Argos AI reading. Run everything with cd rust && make check.

### The three fixed rules

- Always add at the end: the position is the identifier (settings, sources, FICHES index).
- Never rename a variant or a setting key: users' settings are kept by name (Ind is serialised by name). Replace through CONVERSIONS instead.
- Pure Rust, no file and no thread in the computation or drawing: the same code runs on the web (wasm32).

With the split of the app into modules, a native indicator will be declared through a registry (no more hand-written enum entries) and its files will move to rust/chart-et-analyse/h-argos-script/. The manifest and the module API (WASM path) do not change. This section will be updated then.

## FAQ

1. WASM module or native? Module: for anyone, no app rebuild, output limited to lines, labels and cards. Native: for contributors, full drawing, needs an app build.
2. Is there a trait to implement? No. Module: fn run(Input) -> Output plus entry_data!(run). Native: plain functions plus match branches on the enum Ind.
3. Which target? wasm32-unknown-unknown, in --release.
4. Why integers in a module? So the result is identical on PC, phone and web; the ABI passes everything as i64 with price_scale / volume_scale, and each line carries its own scale.
5. How many bars does a module receive? At most 50,000; the oldest are cut, and more are cut if the encoded input would exceed 4 MiB.
6. Can a module use the Internet or call an AI? Not in Trading: Network, Ai and Model are refused. Only the private folder (1 MiB, read and write) can be granted.
7. How much time and memory? 200,000,000 fuel per call, 16 MiB memory, budget_secs of time (2 s by default, 120 s at most).
8. How do I install a module on PC? Put name.wasm and name.json in Downloads, then 🧩 Modules page → "📂 Installer un module". On the web the same button opens a file picker.
9. Must a module be signed? Not yet: no signature is checked; the approval is the SHA-384 of the .wasm, accepted at install time.
10. Native: on the price or in a band? Plot.sub false = on the price, true = band (plus oscillator()); default band height 120 px.
11. Where do colours go in a native indicator? User-adjustable: color(...) in PARAMS, read with col(&inp, key) then on_chart; fixed: hex(...); theme colours: palette::up() / down().
12. How is the name translated? Add the phrase to DICT in argos-render/src/i18n.rs; otherwise it stays in French.
13. When is it recomputed? When the bar count, the last bar's time or close, or the active list changes, at most every 500 ms on PC and 1.5 s on phone. Drawing is redone every frame.
14. Does a native indicator run on the web? Yes: computation and drawing are pure Rust and checked for wasm32 by make check.
15. Free buy/sell signals? Yes for a line indicator: signals(crosses(a, b), "Achat", "Vente") in plot().
16. Free summary table? Yes: fill Plot.tableau; position and size are adjustable (tblPos / tblSize).
17. Can I rename a variant or a setting key? No: users' settings are kept by name. Use CONVERSIONS for a replacement.
18. Why add at the end? FICHES[i as usize] and source_ext use the position as identifier.
19. Anything simpler than Rust? Yes: an Argos Script script stored as a catalogue fiche (Script(include_str!(...pine))) gives settings, drawing and the { } button without render code; SMA, WMA, HMA, VWMA, SMMA and MA Ribbon work this way.
20. Is there a contributor guide in the repository? Not yet; this file and the French doc "Créer un indicateur en Rust" are the guides. For Argos Script, see 2026-11-22-argos-script-llms-v1.txt in the same documents/ folder.
